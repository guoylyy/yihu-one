# 设计：组织与空间（多公司 / 客户隔离，REQ-06）

> 状态：**一期已实现** · 2026-10-11 · 决策 6.7：一个应用可以授权给多个空间

## 目标

一套以虎 One 里开多个**空间**：自己公司、兄弟公司、客户各一个。不同空间的人互相看不到——同事、部门、应用、Skill、知识库、轻应用数据都按空间分开；平台管理员跨空间管理。不再为每家公司单独起一套实例。

## 规则

| 东西 | 属于 | 谁看得到 |
| --- | --- | --- |
| 人、部门 | 一个空间 | 同空间的人；管理员 |
| 应用（含 AI 助手、轻应用、Skill、外部 / 代码应用） | 一个所属空间 + 管理员分享给的空间（`extraSpaceIds`） | 这些空间里、再按原来的可见范围（部门 / 人 / 角色）筛一次 |
| 知识库 | 一个空间 | 同空间、再按原来的知识库可见范围 |
| 轻应用的数据 | 写入者所在空间 | 只有同空间的人（应用分享给多个空间时，各空间的数据自动分开） |

- 判断只在一处：`services/spaces.js`（`appInSpace` / `spaceWhere`），由 `apps.visibleTo` 做「空间 → 组织 → 人」三段收敛。市场、工作台、首页、AI 工具、MCP、统一登录都走它
- 统一登录、OIDC、用户主数据接口都带上**用户所在空间**（`space: { id, code, name }`；OIDC 是 `space` / `space_name`）。应用分享给多个空间时，**应用要按空间分开自己的数据**
- 应用的用户主数据接口只给应用所在空间（含分享空间）的人
- 管理员（`ADMIN`）是平台管理员：跨空间可见，管理页面可以按空间筛
- 只有一个空间时，界面上不出现「空间」（`/api/me` 的 `multiSpace`）

## 数据模型与迁移

迁移 `20261011005737_spaces`：

- 新表 `Space { id, code, name, kind(INTERNAL / CUSTOMER), sort }`，插入 `id = 1` 的默认空间
- `User.spaceId`、`Department.spaceId`、`App.spaceId`、`KnowledgeBase.spaceId`、`AppData.spaceId`，都是 `NOT NULL DEFAULT 1`——**老数据全部归默认空间，没有孤儿**，单空间的平台行为不变
- `App.extraSpaceIds`（JSON，可空）

回滚（先确认只有默认空间，或其他空间的数据已经不要了）：

```sql
ALTER TABLE `User` DROP COLUMN `spaceId`;
ALTER TABLE `Department` DROP COLUMN `spaceId`;
ALTER TABLE `App` DROP COLUMN `spaceId`, DROP COLUMN `extraSpaceIds`;
ALTER TABLE `KnowledgeBase` DROP COLUMN `spaceId`;
ALTER TABLE `AppData` DROP COLUMN `spaceId`;
DROP TABLE `Space`;
DELETE FROM `_prisma_migrations` WHERE `migration_name` = '20261011005737_spaces';
```

然后把平台代码回到这次改动之前的版本。

## 怎么用

1. 「管理 → 空间」新建空间（如 `acme` 示例科技）
2. 「管理 → 用户与部门」选这个空间：建部门、加人；或「从飞书 / 钉钉同步」——新同步进来的部门和人放进当前选的空间
3. 「管理 → 应用」决定哪些应用给它用：应用的「所属空间」，或「也给这些空间用」
4. 「管理 → 知识库」新建时选空间

5. 「管理 → 空间 → VI」给这个空间设自己的平台名称、LOGO 和配色（不设 = 跟随平台的「外观与主题」），空间里的人登录后看到的就是自己公司的样子

规则约束：人只能挂本空间的部门；下级部门跟上级同空间；只能删空的空间；默认空间不能删。
