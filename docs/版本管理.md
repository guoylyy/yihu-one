# 版本管理

以虎 One 平台的版本号是 **`主版本.次版本.修订号`**（[语义化版本](https://semver.org/lang/zh-CN/)），现在是 **0.1.0**。

## 规则

| 版本段 | 什么时候升 | 例子 |
| --- | --- | --- |
| 修订号 | 只修问题，不加功能、不改接口 | 0.1.0 → 0.1.1 |
| 次版本号 | 加功能；**0.x 阶段**也包括不兼容的调整（写进更新说明的「升级注意」） | 0.1.1 → 0.2.0 |
| 主版本号 | 1.0 = 正式版：接入接口（SDK、统一认证、OIDC、MCP、清单）稳定，之后不兼容的改动才升主版本 | 0.9.0 → 1.0.0 |

- **主版本为 0 就是测试版（Beta）**：界面上版本号旁边显示「Beta」
- 每次迭代结束发一个版本；一个版本发出去（打了 `v<版本>` 标签）就不再改，有问题发修订版

## 在哪里看到版本

- 所有人：左侧栏底部、头像菜单「关于」（还能打开「版本更新说明」`/dev/releases`）
- 管理员：「管理 → 概览」的平台版本卡片（含有没有新版本、一键升级）
- 接口：`GET /api/me` 的 `platform: { version, channel }`（`channel` 是 `beta` / `stable`）
- 宿主机：`yh version`，根目录 `VERSION`

界面上的版本以宿主机 `yh` 上报的为准（`report_platform` → `services/upgrade.js` 的 `versionBrief`），没上报过（本地开发）用控制台 `package.json` 里的版本。

## 怎么改版本号

只用脚本改，一处改全：

```bash
./scripts/bump-version.sh 0.2.0
```

它会改根目录 `VERSION`（`yh`、更新包用）、`console/backend` 和 `console/frontend` 的 `package.json` / `package-lock.json`，并在 [版本更新说明](../console/docs/devcenter/releases.md) 顶上加一节待填。然后：

1. 填好这一节：新功能、改动、修复、**升级注意**（0.x 的不兼容调整一定写）
2. 接入相关的变化同时记到开发中心的 [变更记录](../console/docs/devcenter/changelog.md)
3. `cd console/backend && npm test`（`test/version.test.js` 校验几处版本号一致、更新说明里有这个版本）
4. 提交，按 [部署手册「平台升级」](部署手册.md) 打包（`YH_RELEASE_KEY=~/.yihu-one-release.key ./scripts/pack.sh …`，0.2.0 起必须签名）、打标签、发 GitHub Release
