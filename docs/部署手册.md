# 以虎 One · 部署手册

> 适用于平台 0.1.x · 2026-10-11
> 写给**部署工程师**：从零给一家新公司装一套完整的以虎 One，配好、验收、交付。按第 1 节到第 9 节的顺序做；日常运维和升级在第 10、11 节。
> 只想先在自己电脑上看看：`./install.sh --test --demo`（见 [README](../README.zh-CN.md)「快速开始」），不用读这份手册。

---

## 0. 装完是什么样

```
 员工浏览器 / 钉钉 / 飞书 / 企业微信
        │  https://one.<公司域名>/                    控制台：工作台、应用市场、AI 助手、管理
        │  https://apps.one.<公司域名>/apps/<code>/   各代码应用（独立域名，拿不到控制台的登录凭证）
        ▼
 ┌─ 云服务器（公网，1 核 1G 就够）───────────────┐
 │ Caddy：HTTPS 证书 + 按域名转发                │
 │ frps：隧道服务端（端口 7000）                 │
 └──────────────▲──────────────────────────────┘
                │ frp 隧道（平台机器主动连出去，不需要公网 IP）
 ┌─ 平台机器（公司内网，Mac mini 或 Linux 服务器）─────────────────────┐
 │ yh-caddy（入口）  yh-console（控制台）  yh-mysql  yh-redis  yh-frpc  │
 │ yh-<code> …（每个应用一个容器、一个数据库、一个独立网络）             │
 │ yh agent（常驻）：执行控制台里点的安装 / 发布 / 停用，上报状态、备份   │
 └───────────────────────────────────────────────────────────────────┘
```

**一共四步**：

1. 准备机器和域名（第 2~3 节）
2. 在平台机器上执行一条 `install.sh`（第 5 节）
3. 在云服务器上执行一条 `cloud/install.sh`（第 4 节）
4. 打开浏览器，完成初始化和配置（第 6 节）

熟练以后，一家公司半天以内能装完。

## 1. 先做三个决定

### 1.1 单独装一套，还是在已有平台里开一个「空间」

| | 单独一套（推荐给独立公司、客户） | 已有平台里开空间 |
| --- | --- | --- |
| 做法 | 按本手册全流程装 | 在已有平台「管理 → 空间」里新建，见 [多空间设计](设计-多空间.md) |
| 数据 | 完全物理隔离：自己的机器、数据库、备份 | 同一个数据库，按空间隔离（人、部门、应用、知识库互相看不到） |
| 登录 | 用这家公司自己的钉钉 / 飞书 / 企业微信 | **只能用平台已经配好的那一个**钉钉 / 飞书 / 企业微信，或账号密码（还不支持每个空间配自己的登录方式） |
| 外观 | 自己的 VI | 每个空间可以有自己的 VI（名称、LOGO、配色） |
| 适合 | 要用自己飞书 / 钉钉登录的公司、要求数据独立的客户 | 集团内的兄弟公司、小客户，能接受账号密码登录或共用通讯录 |

**一句话判断：要用这家公司自己的飞书 / 钉钉 / 企业微信登录，就单独装一套。**

### 1.2 对外入口

| 方式 | 什么时候用 | 需要什么 |
| --- | --- | --- |
| **B. 云服务器隧道**（推荐） | 平台机器在内网、没有公网 IP（绝大多数情况） | 一台公网云服务器（1 核 1G 就够），两个域名都解析到它 |
| A. 前置反向代理 | 公司已有网关 / Nginx 能转发到平台机器 | 网关把两个域名转到平台机器的 18080 端口，保留 Host 和 `X-Forwarded-*` 头，关掉响应缓冲（AI 助手是流式输出） |

### 1.3 怎么升级

| 方式 | 怎么装 | 怎么升级 | 适合 |
| --- | --- | --- | --- |
| **更新包方式**（公司安装默认用这个） | `install.sh --company …`（装出来的目录里没有 `.git`） | 什么时候升由这家公司自己定：控制台「管理 → 概览」点「升级」，或执行 `./yh upgrade`；不能联网就拷更新包。升级前自动备份，失败自动回滚 | 所有客户、兄弟公司 |
| Git 跟踪方式 | `install.sh --git`，在 Git 检出目录里原地安装 | 跟踪 `release` 分支：发布方执行 `./release.sh` 后，两分钟内**自动**更新 | 只给以虎自己维护、要第一时间跟上最新代码的实例 |

公司安装用更新包方式，这样你在 `main` 上推代码、发 `release` 时，**不会**让每家公司同时自动更新。

## 2. 准备清单（去现场前收齐）

| 要什么 | 谁提供 | 用在哪 |
| --- | --- | --- |
| 平台机器（配置要求见 3.1），能 SSH 或现场操作，有管理员（sudo）权限 | 客户 IT | 第 3、5 节 |
| 一台云服务器（Ubuntu 22.04 / 24.04 或 Debian 12），有 root 权限，能改安全组 | 客户 IT，或以虎代购 | 第 4 节 |
| 两个域名：`one.<公司域名>`（控制台）、`apps.one.<公司域名>`（应用） | 客户 IT（管 DNS 的人） | 第 4 节 |
| 公司代号（小写英文，如 `acme`）、平台名称、公司 VI（主色、LOGO 文件） | 客户 | 第 5、6 节 |
| 钉钉 / 飞书 / 企业微信管理后台的权限（能建「企业自建应用」） | 客户管理员 | 6.3 |
| 一个大模型 API Key（通义 / DeepSeek / Kimi / 智谱 / Claude …） | 客户 | 6.2 |
| 一个群（飞书 / 钉钉 / 企业微信），用来收发布通知和故障报警 | 客户 | 6.5、第 4 节 |
| 异地备份位置（另一台机器的 SSH 地址，可选） | 客户 IT | 6.6 |

## 3. 平台机器

### 3.1 配置要求

| | 最低 | 建议 |
| --- | --- | --- |
| 系统 | macOS 13+ / Ubuntu 22.04+ / Debian 12+（其他 Linux 能跑 Docker 就行） | Mac mini（M 系列）或 Linux 服务器 |
| CPU | 2 核 | 4 核以上 |
| 内存（分给 Docker 的） | 4G | 8G 以上（平台本身约 2G，每个代码应用默认最多用 512M） |
| 磁盘 | 15G 空闲 | SSD，50G 以上（镜像、数据库、每晚备份保留 14 天） |
| 网络 | 能访问 Docker Hub 和 npm，或国内镜像（`--cn`） | 有线网络，固定内网 IP |
| 其他 | 7×24 开机 | 断电后自动开机，接 UPS |

`install.sh` 会检查这些，不够的直接报错或给出提醒。**一台机器只能装一套平台**（容器名、开机服务名都是固定的）。

### 3.2 macOS（Mac mini）

```bash
xcode-select --install
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install colima docker docker-compose jq git
colima start --cpu 4 --memory 8 --disk 100
brew services start colima        # 开机自动启动 Colima
```

系统设置里还要改三处：**关闭睡眠**（「节能」里勾「防止自动睡眠」）、**断电后自动开机**、**这个用户自动登录**（开机自启的服务要等用户登录后才运行）。

### 3.3 Linux（Ubuntu / Debian）

```bash
sudo apt update && sudo apt install -y git jq curl openssl rsync
curl -fsSL https://get.docker.com | sudo sh                   # 国内服务器：| sudo sh -s -- --mirror Aliyun
sudo usermod -aG docker $USER && newgrp docker                # 让当前用户能用 docker（或者退出重新登录）
docker compose version                                        # 确认装了 compose 插件；没有：sudo apt install -y docker-compose-plugin
```

建议用普通用户（不用 root）装平台，开机自启那一步脚本会自己调 `sudo`。

### 3.4 国内网络与内网

- **一般的国内网络**：安装时加 `--cn`。平台的 Caddy / MySQL / Redis / frpc 镜像和控制台构建用的 node 镜像从 `docker.m.daocloud.io` 拉，npm 包走 `registry.npmmirror.com`，Prisma 引擎也从 npmmirror 下载。这三项写在 `yh.env` 的 `IMAGE_MIRROR` / `NPM_REGISTRY` / `PRISMA_ENGINES_MIRROR` 里，可以换成公司自己的镜像。
- **应用也要拉镜像**：`--cn` 只管平台自己。代码应用的 `Dockerfile`（模板里用的是 `node:20-alpine`、`python:3.12-slim`）也拉不动时，给 Docker 配镜像加速：
  - Linux：在 `/etc/docker/daemon.json` 里写 `{"registry-mirrors": ["https://docker.m.daocloud.io"]}`，然后 `sudo systemctl restart docker`
  - macOS（Colima）：`colima stop && colima start --edit`，在 `docker:` 下面加 `registry-mirrors: [https://docker.m.daocloud.io]`
  - 应用里的 `npm install` / `pip install` 也要走国内源：在应用的 Dockerfile 里设 `npm config set registry …` 或 `pip install -i …`
- **完全不能上网的内网**：需要公司内部有 Docker 镜像仓库和 npm 镜像，把上面三个变量指过去；用 `--src` 装拷进来的更新包，加 `--offline` 不联网查新版本。大模型也要选内网能访问到的（或私有部署的）。

## 4. 云服务器（隧道入口）

只有 1.2 选了 B 才需要这一节。

1. **安全组**：入方向放行 TCP **7000**（隧道）、**80**、**443**
2. **DNS**：`one.<公司域名>`、`apps.one.<公司域名>` 加两条 A 记录，指向云服务器的公网 IP
3. 把平台目录里的 `cloud/` 文件夹拷到云服务器（`scp -r cloud root@<IP>:/opt/yihu-cloud`），然后在云服务器上执行：

   ```bash
   cd /opt/yihu-cloud
   sudo DOMAIN=one.example.com APPS_DOMAIN=apps.one.example.com FRP_TOKEN=<平台机器 yh.env 里的 FRP_TOKEN> \
        INSTALL_DEPS=1 CN=1 \
        ALERT_WEBHOOK=<群机器人地址> ./install.sh
   ```

   | 变量 | 说明 |
   | --- | --- |
   | `DOMAIN` / `APPS_DOMAIN` | 控制台域名和应用域名 |
   | `FRP_TOKEN` | 平台机器装完后 `install.sh` 会打印出来，`yh.env` 里也有。**必须和平台机器一致，不要发到群里** |
   | `INSTALL_DEPS=1` | 新服务器用：没装 Docker、Caddy 的自动装上（只支持 Ubuntu / Debian） |
   | `CN=1` | 国内服务器用：Docker 和 frps 镜像走国内源 |
   | `ALERT_WEBHOOK` | 可选，但建议配：每 5 分钟从云服务器访问一次平台，打不开就往群里报警（平台机器关机、断网时，只有它能报出来）。钉钉用加签的，再加 `ALERT_DINGTALK_SECRET` |

   脚本只在 Caddy 配置里追加属于自己的一段，校验通过才 reload，不影响服务器上的其他网站。重复执行只会更新这一段。
4. 回到平台机器执行 `./yh doctor`：「隧道已连上云端」「公网访问」两项都应该通过

> 一台云服务器默认只服务一家公司（frps 的端口和容器名是固定的）。如果几家公司要共用一台，就给每家另起一个 frps（用不同的 `bindPort` 和 7080 端口），平台机器 `yh.env` 里的 `FRP_SERVER_PORT` 跟着改，云服务器上的 Caddy 转发到对应端口。

## 5. 一条命令安装

在平台机器上：

```bash
git clone https://github.com/guoylyy/yihu-one.git && cd yihu-one
./install.sh --company acme \
  --url https://one.example.com \
  --apps-url https://apps.one.example.com \
  --frp-server <云服务器公网 IP> \
  --cn --demo
```

不想 clone 代码的话（要等发布页上有安装包以后），也可以一条命令装：

```bash
curl -fsSL https://github.com/guoylyy/yihu-one/releases/latest/download/install.sh | bash -s -- \
  --company acme --url https://one.example.com --apps-url https://apps.one.example.com --frp-server <IP> --cn --demo
```

手里拿到的是更新包（`yihu-one-<版本>.tar.gz`）时：`./install.sh --src yihu-one-0.1.0.tar.gz --company …`。

| 参数 | 说明 |
| --- | --- |
| `--company` | 公司代号（必填），写进 `yh.env` 和交付单 |
| `--url` | 控制台地址（必填） |
| `--apps-url` | 应用独立域名。**生产必须配**：不配的话，代码应用和控制台同源，应用页面里的脚本能读到用户的控制台登录凭证 |
| `--frp-server` | 云服务器公网 IP（走隧道入口时填）；用前置反代就不填 |
| `--cn` | 国内网络（见 3.4） |
| `--demo` | 装两个演示应用 `demo-node`、`demo-py`，装完就能体验统一登录和 AI 工具；体验完可以在控制台移除 |
| `--dir` | 装到哪个目录（默认 `~/yihu-one`）。在 Git 检出里执行时，脚本会把**已提交的当前版本**导出到这个目录，按更新包方式安装 |
| `--no-openhex` | 不装 OpenHex 模型接入 SDK（它的开源协议还没定，对外分发时用这个参数） |
| `--offline` | 不联网查新版本（升级靠拷更新包）；`--upgrade-url` 可以换成你们自己的更新地址 |
| `--yes` | 不确认，直接装（脚本化部署时用） |

脚本依次做七步：

1. **检查机器**：系统、依赖、Docker 的内存和 CPU、磁盘、端口、网络、域名解析
2. **准备平台文件**
3. **写配置**：生成 `yh.env` 和全部密钥，权限 600
4. **安装平台**：拉镜像、构建控制台，第一次要 3~10 分钟
5. **开机自启 + 常驻 agent + 每晚 02:30 备份**
6. **装演示应用**（加了 `--demo` 时）
7. **自检**（`yh doctor`），并生成**交付单** `~/yihu-one/交付单-<公司>.md`

- 中途失败（多半是网络问题）：解决后**直接重新执行同一条命令**，已经生成的配置和密钥不会变
- 装完后终端会打印云服务器上要执行的那条命令（带隧道令牌），接着做第 4 节
- 不想用浏览器向导、要用脚本建管理员：装之前在 `~/yihu-one/yh.env` 里写一行 `ADMIN_INITIAL_PASSWORD=<密码>`

## 6. 初始化与配置

打开 `https://one.<公司域名>`，第一次会进入**初始化向导**：设置管理员账号和密码、平台名称、组织名称（向导会预置一个通用 AI 助手）。完成后，工作台顶部有一个「开始配置」清单，按下面的顺序做。

### 6.1 公司 VI（外观）

在「管理 → 系统设置」里：

- **基本信息**：填平台名称、英文名，上传公司 LOGO（正方形 PNG / SVG，不超过 200KB；浏览器标签页图标也用它）
- **外观与主题 → 视觉识别（VI）**：先选一套预设（默认是「以虎科技 VI」，另有「经典蓝」），再按公司 VI 改主色、强调色、底色、文字色、圆角、阴影、字体。右边实时预览，保存后全站立即生效
- 一套平台里有多家公司（多个空间）时，每个空间还可以在「管理 → 空间 → VI」设自己的名称、LOGO 和配色

### 6.2 模型与 AI

在「管理 → 模型与 AI」里加一个模型（OpenAI 兼容的：通义、DeepSeek、Kimi、智谱等；或者 Anthropic、OpenHex），点「测试」确认能连上。AI 助手能用的工具 = 平台通用工具 + 用户能看到的应用提供的 MCP 工具。生成轻应用需要一个写代码能力强的模型，在「审核与市场 → 市场设置」里指定。

### 6.3 登录方式

账号密码登录默认开着。钉钉、飞书、企业微信可以任选，也可以同时打开：登录页上各有一个按钮，在对应的客户端里打开平台时自动免登；同一个人用不同方式登录，只要手机号或邮箱一致，就是同一个账号。三家都要先建一个「企业自建应用」，把凭证填进「管理 → 登录方式」，再打开开关：

| 平台 | 在哪建应用 | 填到控制台 | 在平台后台里要配的地址 |
| --- | --- | --- | --- |
| 钉钉 | 钉钉开发者后台 → 应用开发 → 企业内部应用 | Client ID、Client Secret、CorpId | 登录与分享 → 回调域名 `https://<域名>/auth/dingtalk/callback`；H5 首页 `https://<域名>/` |
| 飞书 | 飞书开发者后台 → 企业自建应用 | App ID、App Secret | 添加「网页应用」能力，桌面端 / 移动端主页填 `https://<域名>/`；安全设置 → 重定向 URL 填 `https://<域名>/auth/feishu/callback`；权限：获取用户基本信息（要按手机号对上已有用户，再加手机号、邮箱权限；要同步通讯录，再加「获取部门组织架构信息」「读取成员基本信息」）；**发布时可用范围要选全员，或至少包含要用的人**，否则其他人登录会被飞书拦下，提示「没有使用权限」 |
| 企业微信 | 管理后台 → 应用管理 → 自建应用 | CorpID、AgentId、Secret | 应用主页填 `https://<域名>/`；「网页授权及 JS-SDK」的可信域名、「企业微信授权登录（Web 网页）」的授权回调域都填 `<域名>`；可见范围选要登录的人 |

「管理员名单」里的人（钉钉填 userid，飞书填 open_id，企业微信填 userid；飞书和企业微信也可以填手机号）第一次登录时自动成为管理员。**飞书务必填 open_id（ou_ 开头），不要填 union_id（on_ 开头）或 user_id——填错了不会生效，也不会报错**。

### 6.4 用户与部门

可以手动添加，也可以「从钉钉 / 飞书同步」（先预览，再同步）。**至少再设一个管理员**。没同步过的人第一次登录时会自动建号；可以关掉这个功能，改成只允许管理员建过的人登录。

### 6.5 发布通知

在「系统设置 → 发布通知」里配群机器人（飞书 / 钉钉 / 企业微信可以配多个），点「发测试消息」确认能收到。机器人的安全设置用关键词「发布」，或者用钉钉的「加签」。平台升级、应用发布结果、公网打不开，都会发到这里配的群。

### 6.6 备份

每晚 02:30 自动备份所有数据库和数据目录到 `~/yihu-one/backups/`，保留 14 天（天数在 `yh.env` 的 `BACKUP_KEEP_DAYS` 里改）。**建议再配一个异地备份**：在 `yh.env` 里写 `BACKUP_REMOTE=user@host:/path`（走 rsync over ssh，要先配好免密登录），然后执行 `./yh start`。

还要把 **`yh.env` 存进公司的密码库**：里面的加密密钥一旦丢了，数据库里加密保存的模型 Key、登录凭证就都解不开了。

### 6.7 接入应用

- 已有的系统（SaaS、老 ERP 等）：在「创作中心 → 登记外部应用」里登记。自带「通用 OIDC 登录」的系统（GitLab、Grafana…）填几项配置就能统一登录，见开发中心 `/dev/oidc`

## 10. 日常运维

```bash
./yh status               # 各应用的状态、内存、版本
./yh doctor               # 全面自检
./yh version              # 平台版本
./yh logs console -f      # 控制台日志；看应用的：yh logs <code>
./yh backup               # 手动备份一次（每晚 02:30 会自动备份）
./yh restore <code> backups/<时间>/app_<code>.sql.gz    # 恢复某个应用的数据库；恢复控制台：yh restore console …/yh_console.sql.gz
./yh passwd admin         # 忘了管理员密码时用
./yh up console           # 重新构建控制台
```

日志在这些地方：`backups/agent.log`（agent）、`backups/ops/`（每次控制台操作）、`backups/notify.log`（通知）、`backups/deploy-history.tsv`（发布记录）。

| 做什么 | 在控制台里 | 在服务器上 |
| --- | --- | --- |
| 安装应用 | 应用 → 从 Git 安装应用 | `yh add <code> --git <仓库>` → `yh up <code>` |
| 用模板新建应用 | — | `yh new <code> --from node\|python` → `yh up <code>` |
| 发布新版本 | 应用 → 发布 | `yh update <code>` |
| 自动发布 | 应用仓库推到 `release` 分支后，agent 两分钟内自动发布，失败自动回滚 | `yh history` 看记录 |
| 停用 / 启动、重启、看日志 | 更多 → 停用；启动、重启、日志 | `yh down` / `yh up`、`yh restart`、`yh logs <code> -f` |
| 移除 | 更多 → 移除（会先备份到 `backups/removed/`） | `yh remove <code>` |
| 审核员工发布的应用 | 审核与市场 | — |

**员工自己发布应用**：员工在「创作中心」做 AI 助手、轻应用（这两种不占容器），或者登记外部应用；给某人设了「开发者」角色后，他还能提交代码应用。上架全公司、分享外部应用、提交代码应用，都要管理员在「管理 → 审核与市场」里审核。代码应用审核通过后由 agent 自动安装，所以 **agent 必须一直在跑**。

## 11. 平台升级

版本号的规则（x.y.z，0.x 是 Beta）见 [版本管理](版本管理.md)。

**客户这边（更新包方式）：**

```bash
./yh upgrade --check                         # 查有没有新版本
./yh upgrade                                 # 下载并升级到最新版本
./yh upgrade --package yihu-one-0.2.0.tar.gz # 不能联网时：用拷进来的更新包升级
```

- **能联网**：agent 每 6 小时按 `yh.env` 里的 `UPGRADE_URL` 查一次新版本。有新版本时会在群里通知，控制台「管理 → 概览」也会出现「有新版本」和更新说明，管理员点「升级」就行
- **不能联网**：把 `yihu-one-<版本>.tar.gz`（有 `.sig` 签名文件的话一起）拷到平台机器上，执行 `yh upgrade --package`；或者在概览页点「上传更新包」
- **升级时做了什么**：校验更新包 → 把平台文件和控制台数据库备份到 `backups/upgrade/`（保留最近 5 次）→ 换成新版本的文件 → 重新构建控制台（数据库结构跟着升级）。期间控制台有几分钟打不开，**各应用照常运行**；`yh.env`、应用和应用数据都不动
- **失败自动回滚**：新版本控制台构建失败或起不来时，平台文件和控制台数据库都恢复到升级前，再用旧版本启动。原因见 `backups/upgrade/console-build.log`
- 升级会覆盖平台自带的文件（`platform/Caddyfile`、`platform/compose.yml` 等），不要在这些文件里做本机改动

**Git 跟踪方式**（用 `--git` 装的）：跟踪 `release` 分支自动更新，不用也不能执行 `yh upgrade`。

**发布方（以虎）这边：发一个新版本**

```bash
./scripts/bump-version.sh 0.2.0     # 1) 改版本号，填好 console/docs/devcenter/releases.md 里的更新说明，提交
./scripts/pack.sh --base-url https://github.com/guoylyy/yihu-one/releases/download/v0.2.0
                                    # 2) 打包，生成 dist/yihu-one-0.2.0.tar.gz、latest.json、install.sh（配了签名私钥还有 .sig）
git tag v0.2.0 && git push origin v0.2.0
gh release create v0.2.0 dist/yihu-one-0.2.0.tar.gz dist/latest.json dist/install.sh --title v0.2.0 --notes-file <更新说明>
                                    # 3) 发到 GitHub Releases：latest/download/ 永远指向最新一版，客户的 UPGRADE_URL 默认就是它
```

- 包里只有 Git 里已经提交的文件（`.gitattributes` 里标了 `export-ignore` 的除外）
- `--notes "…"` 写更新说明；`--min <版本>` 要求低于这个版本的机器先升到这个版本
- 签名（正式对外发布前建议打开）：执行 `openssl genrsa -out ~/.yihu-one-release.key 3072 && openssl rsa -in ~/.yihu-one-release.key -pubout -out platform/release.pub`，把公钥提交进仓库，私钥自己保管；打包时用 `YH_RELEASE_KEY=~/.yihu-one-release.key ./scripts/pack.sh`。公钥随某个版本发出去以后，装了那个版本的机器就只接受带签名的更新包
- 想先让一家公司试新版本：只把包发给这一家（`--src` / `--package`），其他公司的 `UPGRADE_URL` 继续指向旧的清单
- 改了 `yh` 里的升级部分或 `scripts/pack.sh`，要跑 `./scripts/upgrade-test.sh`

## 12. 故障排查

| 现象 | 怎么查 |
| --- | --- |
| `install.sh` 拉镜像或 `npm ci` 超时 | 加 `--cn` 重新执行同一条命令；还不行，看 3.4 |
| 提示「Docker 只有 xG 内存」 | macOS：`colima stop && colima start --cpu 4 --memory 8 --disk 100` |
| 提示「这台机器上已经有一套以虎 One」 | 一台机器只能装一套；确认旧的不要了，到旧目录执行 `./yh destroy` |
| 控制台构建失败 | 执行 `docker compose -f platform/compose.yml build console` 看完整输出，多半是网络问题 |
| 公网打开显示「平台暂时连不上」 | 平台机器有没有开机；`docker ps` 里 `yh-frpc`、`yh-caddy` 在不在；看 `docker logs yh-frpc`；云服务器上看 `docker logs yh-frps`；安全组有没有放行 7000 |
| 证书签不下来 | 域名有没有解析到云服务器、80/443 有没有放行；云服务器上看 `journalctl -u caddy` |
| 控制台里的操作一直「排队中」 | agent 没在跑：执行 `./yh doctor`；`./yh autostart` 重新装；看 `backups/agent.log` |
| 应用显示「还没上线，或已停用」 | `./yh status` 看状态，`./yh up <code>` |
| 安装应用失败 | 在控制台里点开这次操作看日志。常见原因：仓库没权限（缺部署公钥）、清单里的 code 和填的不一致、缺 Dockerfile、健康检查不过、拉不动基础镜像（见 3.4） |
| 统一登录报 redirect_uri 不匹配 | 改过 `PUBLIC_URL` / `APPS_URL`：执行 `./yh start`（会逐个重新登记应用） |
| 飞书登录提示「没有使用权限」 | 飞书应用的可用范围没包含这个人，或者应用还没发布版本 |
| 换域名 | 改 `yh.env` 的 `PUBLIC_URL`（和 `APPS_URL`）→ `./yh start` → 在云服务器上用新域名重跑 `cloud/install.sh` → 改钉钉 / 飞书 / 企业微信后台的回调地址 |
| 换机器 | 在新机器上按本手册装好 → 从旧机器的 `backups/` 拷出 `yh_console.sql.gz` 和各应用的备份 → 执行 `./yh restore console …`、`./yh restore <code> …`；`yh.env` 要用旧机器的（密钥必须一致） |

## 13. 安全须知

- `yh.env`、`platform/console.env`、`apps/*/.env` 里有密钥，权限 600，不要发到群里，不要提交进代码库
- 生产模式每次启动都会强制关闭开发登录。平台机器的 18080 端口只监听本机（`LOCAL_HTTP_BIND=127.0.0.1`）——不要改成 `0.0.0.0`，否则内网的人能绕过隧道直连
- **管理员账号等同于服务器权限**（能从 Git 安装代码，并在平台机器上运行），只给可信的人
- **生产环境必须配应用独立域名（`APPS_URL`）**
- 审核员工提交的代码应用时，确认仓库可信、清单里的内存和 CPU 设得合理；应用之间网络是隔离的，但共用同一台机器的资源
- 云服务器上只跑 Caddy 和 frps，不要把平台容器放到公网服务器上

## 14. 卸载 / 重新安装

```bash
./yh destroy        # 删除本机平台的全部容器、数据库、数据目录、密钥和备份（要输入 destroy 确认；要留的备份先拷走）
```

开机自启的服务要另外删：macOS 执行 `launchctl bootout gui/$(id -u)/one.yihu.agent`（还有 `one.yihu.boot`、`one.yihu.backup` 两个，文件在 `~/Library/LaunchAgents/one.yihu.*.plist`）；Linux 执行 `sudo systemctl disable --now yh-agent yh-boot yh-backup.timer`。
