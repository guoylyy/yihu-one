# 以虎 One · 应用清单

> 平台 0.6.10 时的官方应用。版本号取自各应用仓库的 `yh-app.json` / `package.json` / `CHANGELOG.md`，以仓库为准。
> 平台只做配置，装了哪些应用决定了它每天能干什么。这份清单回答三个问题：每个应用管什么事、数据放在哪、AI 能替你做到哪一步。

## 先看这张表

| 应用 | 代码 | 版本 | 数据 | AI 工具 | 发布方式 | 适合谁 |
| --- | --- | --- | --- | --- | --- | --- |
| 收件箱 | `inbox` | 0.2.2 | MySQL | 2 个 | 手动 | 所有人 |
| 会议与纪要 | `meeting` | 0.2.2 | MySQL | 2 个 | 手动 | 经常开会、要跟进决议的团队 |
| 到期台账 | `expiry` | 0.2.4 | MySQL | 2 个 | 手动 | 行政、法务、管合同证照的人 |
| FDE 交付管理 | `fde` | 0.3.1 | MySQL | 110 多个 | 手动 | 做项目交付的工程团队 |
| 人事考勤 | `hr` | 0.3.6 | MySQL | 16 个 | 手动 | HR、部门负责人 |
| 集团财务 | `finance` | 1.4.0 | MySQL | 5 个 | 自动 | 多公司集团的财务 |
| 个人财务 | `personal-account` | 1.5.2 | MySQL | 5 个 | 自动 | 个人记账 |
| 知识库 | `knowledge` | 1.5.4 | SQLite + 宿主机笔记目录（只读） | 无 | 手动 | 有 Markdown / Obsidian 笔记的人 |

几列的意思：

- **数据**：「MySQL」是平台给这个应用单独建的库（清单里 `database: true`，连接串以 `DATABASE_URL` 注入），和其他应用、控制台互相隔离，`yh backup` 每晚一起备份。所有应用另有一个 `apps/<code>/data` 目录挂到容器的 `/data`，备份时一起打包
- **AI 工具**：应用通过 MCP 提供给平台 AI 助手和外部 Agent 的工具数，按当前用户的身份和权限调用。数字是 0.6.10 时各仓库里登记的数量，会随应用版本变化
- **发布方式**：清单里的 `deploy.mode`。「自动」= 应用的 `release` 分支有新提交就自动构建上线；「手动」= 只通知有新版本，管理员在控制台点「发布」

## 怎么装

每个应用一条命令，在平台机器上执行：

```bash
yh add <代码> --git <仓库地址> && yh up <代码>
```

`yh up` 会建库、在控制台登记、构建、挂路由、做健康检查，统一登录和 MCP 自动接好。装好后应用出现在「管理 → 应用」，按可见范围进到大家的工作台和应用市场。

收件箱、会议与纪要、到期台账、FDE 交付管理这四个也在控制台开通向导的「应用」一步里，点一下就装（同样由 `yh agent` 在宿主机上执行）。

## 收件箱 `inbox` · 0.2.2

一句话记待办、派单给同事，批量整理、导入别的系统里的事，每周看规律。

- **典型场景**：开完会随手记一句「周五前把报价发给客户」，指给同事；周一打开看这一周谁手上压着什么
- **数据**：任务存在平台给它建的 MySQL 库里
- **AI 工具（2 个）**：`create_task` 记一条待办，`list_tasks` 查待办。对 AI 助手说「帮我记一下……」就会进收件箱
- **仓库**：<https://github.com/guoylyy/yihu-inbox>

```bash
yh add inbox --git https://github.com/guoylyy/yihu-inbox.git && yh up inbox
```

## 会议与纪要 `meeting` · 0.2.2

记会议、导入纪要，AI 识别会议信息、提炼决议待办风险，按项目归类。

- **典型场景**：把一份会议记录粘进来，得到时间、参会人、决议、带负责人和截止日的待办、风险，归到对应项目下，以后按项目翻
- **数据**：会议和纪要存在平台给它建的 MySQL 库里；提炼用的是平台托管的模型
- **AI 工具（2 个）**：`list_meetings` 列会议，`get_meeting_notes` 取某次会议的纪要。可以问 AI 助手「上周和客户开会定了什么」
- **仓库**：<https://github.com/guoylyy/yihu-meeting>

```bash
yh add meeting --git https://github.com/guoylyy/yihu-meeting.git && yh up meeting
```

## 到期台账 `expiry` · 0.2.4

合同、证照的到期日一本账：上传文件 AI 识别录入，还剩几天一眼看清，到期前主动提醒。

- **典型场景**：把营业执照、租赁合同、资质证书传上来，AI 读出名称和到期日录入；按设定的提前天数主动提醒，不再等过期了才发现
- **数据**：台账存在平台给它建的 MySQL 库里
- **AI 工具（2 个）**：`list_expiring` 查快到期的，`create_expiry` 新登记一条
- **仓库**：<https://github.com/guoylyy/yihu-expiry>

```bash
yh add expiry --git https://github.com/guoylyy/yihu-expiry.git && yh up expiry
```

## FDE 交付管理 `fde` · 0.3.1

项目、里程碑、任务、工时与知识库；工程师和 AI 智能体一起交付。

- **典型场景**：一个交付项目从立项到验收都在这里：拆里程碑和任务、指派、记工时、审批工时、沉淀项目资料；AI 智能体也能领任务、写记录
- **数据**：项目、任务、工时等存在平台给它建的 MySQL 库里
- **AI 工具（110 多个）**：覆盖项目、任务、工时、客户联系人、知识沉淀等日常操作，是目前工具最全的官方应用；另有平台标准的 3 个只读工具（`get_daily_summary`、`get_key_metrics`、`list_pending_decisions`），供老板简报和管理层首页取数
- **仓库**：<https://github.com/guoylyy/yihu-fde>

```bash
yh add fde --git https://github.com/guoylyy/yihu-fde.git && yh up fde
```

## 人事考勤 `hr` · 0.3.6

钉钉 / 飞书 / 企业微信的打卡、请假、出差汇总，年假余额、合同、人员成本、1v1、人员画像。

- **典型场景**：考勤汇总用月历和团队矩阵看；员工自己问 AI「我还剩几天年假」；HR 看哪些劳动合同快到期
- **数据**：员工档案、考勤汇总、合同、1v1 记录等存在平台给它建的 MySQL 库里；打卡、请假、出差数据从钉钉 / 飞书 / 企业微信拉取
- **AI 工具（16 个）**：查本人考勤和年假余额、团队考勤和月度矩阵、请假记录、快到期的合同、人员概况和画像、记 1v1、导入员工档案等，外加平台标准的 3 个只读工具
- **仓库**：<https://github.com/guoylyy/yihu-hr>

```bash
yh add hr --git https://github.com/guoylyy/yihu-hr.git && yh up hr
```

## 集团财务 `finance` · 1.4.0

多公司账户与流水、收付款、工资报销、发票借贷、月结、资金预测。

- **典型场景**：一个集团下几家公司的账户余额和流水放在一起看；老板问「账上还有多少钱」「下个月钱够不够」，直接有数
- **数据**：账户、流水、收付款、发票等存在平台给它建的 MySQL 库里
- **AI 工具（5 个）**：`get_cash_overview` 资金概况，`get_cash_forecast` 未来 30 / 60 / 90 天资金预测，`get_monthly_report` 月报，`list_anomalies` 异常，`list_overdue` 逾期
- **仓库**：<https://github.com/guoylyy/yihu-finance>

```bash
yh add finance --git https://github.com/guoylyy/yihu-finance.git && yh up finance
```

## 个人财务 `personal-account` · 1.5.2

私人账本：净资产、收支、预算、投资持仓、借贷往来、AI 记账。

- **典型场景**：每个平台用户一本独立账本；用 AI 记账，月底看储蓄率和预算执行
- **数据**：账本存在平台给它建的 MySQL 库里，每条数据带用户 id 隔离
- **AI 工具（5 个）**：`get_financial_overview` 财务总览，`get_month_summary` 月度汇总，`get_budget_execution` 预算执行，`get_freedom_overview` 「自由天数」，`simulate_decision` 模拟一笔大支出的影响
- **仓库**：<https://github.com/guoylyy/yihu-personal-account>

```bash
yh add personal-account --git https://github.com/guoylyy/yihu-personal-account.git && yh up personal-account
```

## 知识库 `knowledge` · 1.5.4

手机优先的个人知识库：Markdown 笔记、可控分享与访问审计、双链图谱、AI 总结。

- **典型场景**：电脑上用 Obsidian 写的笔记，在手机上读；把某篇分享给别人，可以设口令和有效期、随时撤销，并留访问记录
- **数据**：不用平台的 MySQL。设置和自己的数据库（SQLite，含分享和访问记录）在 `apps/knowledge/data` 下，`yh backup` 一起备份；笔记本身读宿主机上的目录，只读挂进容器：

  ```bash
  yh mount knowledge library <宿主机上的笔记目录>
  ```

  挂载是可选的，不配就不挂（`yh mount` 的用法见开发中心「应用部署规范 · 宿主目录挂载」）
- **AI 工具**：没有提供 MCP 工具，AI 总结在应用内使用
- **仓库**：<https://github.com/guoylyy/yihu-knowledge>

```bash
yh add knowledge --git https://github.com/guoylyy/yihu-knowledge.git && yh up knowledge
```

## 客户定制应用（不对外发布）

另有三个应用是给一家外贸客户定制的：**外贸 CRM**、**选品库**、**外贸培训**。它们的仓库不公开，不能用上面的命令安装，也不会出现在开通向导里。

列在这里是想让你知道：一家公司专属的业务（获客跟进、产品资料、培训考试）同样是做成应用接到平台上，用的是同一套统一登录、数据库、MCP 和发布流程，控制台不为它们加任何功能。

## 自己做一个

想做自己的应用：`yh new <代码> --from node|python` 从模板开始，规则见 [应用接入规范](应用接入规范.md)，详细文档在开发中心（跑起来的平台上是 `/dev`，仓库里是 `console/docs/devcenter/`）。
