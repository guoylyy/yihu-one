# 计划：0.5.0 本地部署开通（装得上、配得好）

> 状态：**进行中** · 2026-10-14 · 开通向导（第二部分）已实现；安装部分（第一部分）待做

## 目标

帮一家本地公司把以虎 One 装成「自己的工作平台」，要做到：

1. **装得上**：服务器上一条命令，或者只有 Docker 的机器上一条 `docker run`，不需要懂 `yh`、不需要会 Linux
2. **配得好**：装完打开浏览器，跟着**开通向导**一步步把公司信息、外观、模型、登录方式、通讯录、通知、应用都配好；每一步都有说明、能当场测试、能跳过、下次接着来

验收标准：一个只会用浏览器和复制粘贴命令的实施人员，**1 小时内**给一家新公司装好并配到「员工能用钉钉 / 飞书登录、AI 助手能用、老板能收到简报」。

## 现状与差距

| | 现在 | 差距 |
| --- | --- | --- |
| 服务器安装 | `install.sh --company … --url …` 一条命令，带检查、国内镜像、自启、交付单 | 参数要事先查好；**只有内网、没有域名**的公司没有现成写法；控制台每次都要现场构建（3~10 分钟、要能访问 npm） |
| Docker 安装 | 没有 | Windows / NAS / 只给了 Docker 的服务器装不了（`yh` 要 bash 和宿主机的开机服务） |
| 浏览器向导 | 2 步：管理员账号、平台名称 | 外观、模型、登录方式、通讯录、通知、应用都不在里面 |
| 装完之后 | 首页「开始配置」4 项，点进去是各个管理页 | 没有说明、不能当场测试；登录方式要开哪些权限要去翻文档 |

## 一、安装

### 1.1 服务器：交互式安装

- `./install.sh` **不带参数时一问一答**：试用还是正式 → 公司代号 → 怎么访问（有域名 + 云服务器隧道 / 有域名 + 公司网关 / **只在内网用 IP 访问**）→ 国内网络？→ 装演示应用？最后显示一条等价的完整命令（下次可以直接用）
- **内网模式**（新增）：没有域名、不对外，员工在公司内网用 `http://<服务器 IP>` 访问。自动取内网 IP、监听 `0.0.0.0`、不配隧道；提示钉钉 / 飞书 / 企业微信登录需要能从外网回调（内网模式下默认账号密码登录）
- 带参数的写法保持不变（脚本化部署）

### 1.2 Docker：一条 `docker run`

只要有 Docker（Linux、Windows / macOS 的 Docker Desktop、群晖等 NAS）：

```bash
docker run --rm -it -v /var/run/docker.sock:/var/run/docker.sock -v /opt/yihu-one:/opt/yihu-one \
  ghcr.io/guoylyy/yihu-one-installer:0.5.0
```

- 安装器镜像里带 `yh`、`install.sh` 和依赖（bash、jq、git、docker CLI），用宿主机的 Docker 起平台；平台文件放在宿主机的 `/opt/yihu-one`（容器里同一路径，应用的数据目录挂载才对得上）
- **agent 跑成一个容器**（`yh-agent`，`restart: unless-stopped`，挂 docker.sock）：替代 launchd / systemd，Docker 起来它就起来，Windows 也一样
- 之后的运维：`docker exec -it yh-agent yh status` 等（文档给出对照表）
- 限制写清楚：Windows 上 Docker Desktop 要开机自启；`/opt/yihu-one` 要在备份范围里

### 1.3 预构建的控制台镜像

- 每次发版把控制台镜像推到 GHCR（`ghcr.io/guoylyy/yihu-one-console:<版本>`，amd64 + arm64），**安装和升级直接拉镜像**，不再现场构建：安装从 3~10 分钟降到 1~2 分钟，也不需要访问 npm
- 拉不到镜像（内网）时自动退回现场构建；国内网络可以配镜像加速
- **离线包**：发版时额外打一个带全部镜像的离线包（`docker save`），完全不能上网的公司拷进去 `./install.sh --offline-bundle <包>` 就能装

### 1.4 装完

- 终端最后只给一个地址：「打开 http://… 继续开通」，剩下的都在浏览器里
- 交付单保留，并在开通向导完成时补全（见 2.3）

## 二、浏览器开通向导

装完第一次打开平台进向导（替换现在的 2 步向导）。之后管理员在「管理 → 开通向导」里随时回来，首页「开始配置」卡片改成显示向导进度。

### 2.1 步骤

| # | 步骤 | 做什么 | 当场测试 | 能跳过 |
| --- | --- | --- | --- | --- |
| 1 | 管理员账号 | 账号、姓名、密码（现有） | — | 否 |
| 2 | 公司信息 | 平台名称、公司名称、LOGO、时区 | — | 否 |
| 3 | 外观 | 选 VI 预设，改主色 / LOGO，右边实时预览（复用「外观与主题」编辑器） | 预览 | 是（用默认） |
| 4 | 大模型 | 选厂商（通义 / DeepSeek / Kimi / 智谱 / 豆包 / Claude / 其他 OpenAI 兼容），只填 API Key，地址和模型名自动带出；可选再加一个向量模型（知识库用） | 「测试」发一句话 | 是 |
| 5 | 登录方式 | 选用哪些（账号密码 / 钉钉 / 飞书 / 企业微信）。选了某一家就在页面上列出：去哪建应用、**要开的权限**（同开发中心「登录方式配置」）、回调地址（自动生成，一键复制）、填凭证；企业微信的可信域名验证文件也在这里填 | 「测试连接」：用凭证换一次 token，告诉你哪一项不对；「用 XX 登录试一下」 | 是（只留账号密码） |
| 6 | 人员 | 从钉钉 / 飞书同步通讯录（先预览）、或上传 Excel / CSV、或手动加；指定其他管理员和部门负责人（老板助理、管理层首页按它） | 预览人数、部门数 | 是 |
| 7 | 消息通知 | 群机器人（发布通知、故障报警）；个人消息（简报推送，钉钉要填 AgentId） | 「发一条给我」 | 是 |
| 8 | 应用 | 勾选要装的：老板助理（已预置，可改可见范围）、官方应用（如 FDE 交付管理）、演示应用；已经在用的系统登记成外部应用（填地址） | 安装进度 | 是 |
| 9 | 完成 | 汇总：哪些配好了（绿）、哪些跳过了（黄）、下一步建议；一键开通自己的每日经营简报；下载交付报告 | — | — |

### 2.2 规则

- 每一步保存后立即生效，中途关掉浏览器下次从断点继续（进度存在系统设置 `onboarding`）
- 只有管理员能看到向导；向导里的每个配置和管理页里的是同一份（改哪边都一样）
- 不需要的步骤可以跳过，完成页和首页会一直提示「还有 X 项没配」，直到配好或点「不需要」
- 测试按钮都不改数据（测试连接、发一条给自己除外）

### 2.3 平台需要新增的

- 登录方式「测试连接」接口：钉钉 / 飞书 / 企业微信各用凭证换一次 access token，返回人能看懂的错误（凭证错 / IP 不在可信列表 / 应用没发布……）
- 大模型厂商预设表（地址、默认模型、向量模型）
- 通讯录 Excel / CSV 导入（模板下载、预览、校验、导入）
- 官方应用清单与一键安装（平台内置一份清单：名称、介绍、Git 地址；管理员勾选后排队安装，复用「从 Git 安装」）
- 交付报告：把交付单（安装信息）和向导结果合成一页，可下载 / 打印

## 三、文档与测试

- 部署手册改成「装 → 打开浏览器开通」两步走，Docker 安装单列一节；开发中心「登录方式配置」和向导第 5 步共用同一份内容
- selftest：新向导各步骤的接口（含跳过、断点续开、只有管理员能用）；安装器镜像在 CI 里跑一遍 `docker run` 安装 + `yh doctor`
- 在一台干净的 Linux 服务器和一台 Windows（Docker Desktop）上各从零装一遍，记录用时

## 四、交付顺序

1. **开通向导**（2.1 ~ 2.3）：最直接改善体验，现有安装方式就能用上
2. **交互式安装 + 内网模式**（1.1、1.4）
3. **预构建控制台镜像**（1.3）：装得快、内网装得上
4. **Docker 安装器 + agent 容器**（1.2）、离线包
5. 文档、自测、两台机器实测 → 发 0.5.0

预计：1 约 3~4 天，2 约 1 天，3 约 1 天，4 约 2~3 天，5 约 1 天。
