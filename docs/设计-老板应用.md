# 设计：给老板的应用（每日经营简报、老板助理、老板首页）

> 状态：**已实现（0.4.0）** · 2026-10-14 · 开发者文档见开发中心 [让应用出现在老板的简报里](../console/docs/devcenter/briefing.md)

## 目标

老板决定平台留不留。老板不会去点开一个个系统，他要的是：**不用问人就知道公司在发生什么，并且能在手机上直接拍板**。这一期做三样：

| | 是什么 | 老板的体验 |
| --- | --- | --- |
| **每日经营简报** | 每天早上 8 点（时间可改）推到老板的钉钉 / 飞书 / 企业微信 | 一屏看完：关键数字、昨天的变化、风险、需要您决定的事；点进去能接着问 |
| **老板助理** | 预置的 AI 助手：能读所有应用和知识库，先说结论、给数字和出处、不编、要动手先确认 | 「这个月哪些项目有风险？」「销售部本周进展如何？」「帮我回复王总：同意方案二」 |
| **老板首页** | 首页模板：关键指标、待我决策、风险动态、最新简报、老板助理 | 打开平台第一眼就是公司状况 |

三样都**不绑定具体业务**：数据来自装在平台上的应用（FDE 交付管理、审批、CRM……），装的应用越多，简报越丰富。

## 一、平台能力（这期新增）

### 1. 应用的标准工具（约定，不是新接口）

应用想出现在老板的简报和首页上，就在自己的 MCP 里实现下面三个**只读**工具（`readOnlyHint: true`，以当前用户身份调用，按他的权限给数据）。名字固定，平台按名字认：

| 工具 | 参数 | 返回 | 用在哪 |
| --- | --- | --- | --- |
| `get_key_metrics` | `period`：`today` / `week` / `month`（默认 `month`） | `{ metrics: [{ name, value, unit?, change?, trend?: "up"\|"down"\|"flat", good?: true\|false, note?, url? }] }`，3~8 个 | 简报的「关键数字」、首页指标卡 |
| `get_daily_summary` | `since`：ISO 时间（默认 24 小时前） | `{ items: [{ title, detail?, level: "info"\|"warn"\|"risk", at?, url? }] }`，最多 20 条，风险在前 | 简报的「变化与风险」、首页风险动态 |
| `list_pending_decisions` | 无 | `{ items: [{ id, title, detail?, requester?, deadline?, url? }] }`，**等这个人拍板**的事 | 简报的「需要您决定」、首页待我决策 |

- 三个都可选，实现几个算几个；没实现的应用照样能被老板助理问到（用它的其他工具）
- `url` 指回应用里的详情页，简报和首页上可以直接点进去
- 只返回这个人有权看的；数字给原值和单位，不要预先拼成句子（平台和模型负责表述）
- 开发中心写一页《让应用出现在老板的简报里》，FDE 交付管理作为第一个实现：关键指标（进行中项目、本月工时、逾期任务、按期率）、动态（项目变红 / 里程碑完成 / 任务逾期）、待决策（待审批工时、待验收交付）

### 2. 平台工具 `get_business_overview`

内置一个只读工具，**一次并行调所有可见应用的这三个标准工具**，合成一份：

```json
{ "since": "...", "apps": [ { "app": "FDE 交付管理", "code": "fde", "metrics": [...], "events": [...], "decisions": [...], "error": null } ] }
```

- 简报、老板助理、首页卡片都用它，模型不用逐个应用去试（省 token、不会漏）
- 每个应用 10 秒超时；某个应用挂了只在它那一项标 `error`，不影响其他

### 3. 定时 AI 任务

**谁都能用**（不只老板）：「每天 8 点给我一份经营简报」「每周五 17 点总结本周项目进展」。

- 定一个时间（每天 / 工作日 / 每周某天 + 几点）和一段话，**以创建者本人的身份**跑一次 AI 助手（可以指定用哪个助手，如老板助理），结果：
  - 存成一个对话，在 AI 助手里能看到、能接着问
  - 推到本人的钉钉 / 飞书 / 企业微信（复用 0.2.0 的个人消息），带「查看详情」链接；没绑定的只存对话
- **定时任务里不执行写操作**：只给只读工具（没有人在旁边点确认）。要动手的事写进结果里，让人点进去确认
- 入口：AI 助手里直接说「每天早上 8 点给我发经营简报」（新工具 `create_scheduled_task`，写操作，要确认）；个人中心「定时任务」里看、改、停、立即跑一次
- 时区：系统设置新增「时区」，默认 `Asia/Shanghai`
- 实现：控制台进程里每分钟检查一次到点的任务（数据库里抢占，重启不丢不重）；单个任务最多跑 2 分钟；每人最多 10 个任务（系统设置可改）；连续失败 3 次自动停用并通知本人
- 数据：新表 `ScheduledTask { id, userId, name, prompt, agentAppId?, schedule(JSON), timezone, enabled, nextRunAt, lastRunAt, lastStatus, lastError, lastConversationId, failCount }`，迁移只加表

## 二、三个应用

### 老板助理（预置 AI 助手）

- 平台预置（新装和升级时都建好，管理员可以改设定、改谁能看见；默认只给管理员和部门负责人）
- 工具：**所有只读工具**（平台通用 + 可见应用的只读工具 + `get_business_overview`）。助手设定里新增「全部只读工具」选项，应用以后新增的工具自动可用
- 设定要点：先结论后细节；数字带单位和出处（哪个应用）；不确定就说不知道；涉及写操作只给建议和入口，不替老板动手

### 每日经营简报（定时任务模板）

- 「老板助理」页面上一个按钮「每天给我发简报」：一键创建定时任务（默认工作日 8:00，可改）
- 固定的简报格式（写在任务的提示里，可改）：
  1. 一句话总评
  2. 关键数字（变化、好坏）
  3. 风险与变化（按严重程度）
  4. **需要您决定的事**（谁、什么事、截止时间、链接）
  5. 建议今天关注的 1~2 件事
- 推送正文控制在一屏（钉钉工作通知 / 飞书卡片的长度限制），完整版在对话里
- 第一次创建时立即跑一次，让老板马上看到效果

### 老板首页（首页模板）

- 「编辑首页」新增「套用模板：管理层」，管理员可以设为「管理员和部门负责人的默认首页」
- 卡片（都是现有卡片类型 + 新数据源）：
  - 问候 + 老板助理输入框
  - **关键指标**：数字卡片，数据来自 `get_business_overview` 的 metrics
  - **待我决策**：列表卡片，来自 decisions，点击直达
  - **风险与动态**：列表卡片，来自 events，风险在前
  - **最新简报**：显示最近一次简报的总评，点开看全文
  - 常用应用

## 三、不做的（这期）

- 待我决策的「一键批复」：先链到应用里处理；以后再做统一批复
- 周报汇总、跨应用的自定义报表
- 简报按部门拆分、发给多人（这期只发给创建者本人）

## 四、交付顺序

1. 平台：标准工具约定 + `get_business_overview` + 定时 AI 任务（含个人中心页面、助手工具、时区设置）
2. 老板助理（预置）+ 每日经营简报（模板与一键创建）+ 老板首页模板
3. FDE 交付管理实现三个标准工具；开发中心文档
4. 自测（selftest 加：标准工具聚合、定时任务到点执行与推送、只读限制）→ 发 0.4.0

## 已确认（2026-10-14）

三个标准工具的名字和格式如上；定时任务只读、只发给本人；老板助理默认只给管理员和部门负责人（可见范围的 `LEADER`）；简报默认工作日 8:00。
