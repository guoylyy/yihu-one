# 以虎 One · 发布方式（隧道转发模式）

> 生产推荐的部署形态。平台机器在内网，公网服务器只做 TLS 和转发。从零安装见 [部署手册](部署手册.md)，整体结构见 [架构说明](架构说明.md)。
> 部署目录就是本仓库的一份检出：平台靠它自更新，**不要在部署目录里手工改源码**。

---

## 0. 一句话

**真实服务跑在内网机器，公网服务器只做门。**

```
浏览器 ──HTTPS──► 云服务器（公网）
                    Caddy :443  只做 TLS 终止 + 按域名转发
                    frps :7000  隧道服务端
                        │  frp 隧道（内网机器主动出站，不需要公网 IP）
                        ▼
                  内网平台机器 ──► yh-caddy ──► yh-console / 各应用容器 / MySQL / Redis
```

服务器不跑业务：构建、重启都在平台机器上，隧道自动生效，云服务器配置很低也够用。

---

## 1. 关键配置（`yh.env`）

改完执行 `./yh start` 生效。

| 键 | 生产值 | 说明 |
| --- | --- | --- |
| `PLATFORM_MODE` | `production` | 生产模式强制关闭开发登录 |
| `PUBLIC_URL` | `https://one.example.com` | 用户访问的域名（隧道外部域名，不是本机地址） |
| `APPS_URL` | `https://apps.one.example.com` | **建议配**：应用独立域名，代码应用和控制台不同源，见第 2 节 E |
| `LOCAL_HTTP_BIND` | `127.0.0.1` | **只监听本机**，外部流量必须经隧道进来 |
| `LOCAL_HTTP_PORT` | `18080` | yh-caddy 的本机端口 |
| `FRP_SERVER_ADDR` | `<云服务器 IP>` | 填了才启用隧道（`platform/frpc.toml` 由 `yh` 生成，勿手改） |
| `FRP_SERVER_PORT` | `7000` | frps 端口 |
| `FRP_TOKEN` | 密钥 | 必须和云服务器 frps 一致 |
| `PLATFORM_BRANCH` | `release` | 平台自身跟踪的发布分支 |
| `WATCH_INTERVAL` | `120` | 应用发布分支轮询间隔（秒） |
| `EXTRA_TUNNELS` | 留空 | 可选：把内网独立服务挂到子域名，见第 2 节 D |

平台建库规则：每个应用一个库 `app_<code>`（`-` 转 `_`）。导入已有数据时导进 `app_<code>`；导入会按 dump 内容重建表，只影响这个应用自己的库。

## 2. 日常发版

### A. 平台自身（控制台 / `yh` 脚本 / 平台组件）

**只在 `main` 上开发，`release` 只由 `./release.sh` 更新。**

```bash
git checkout main && git pull --rebase
# 改代码 → 本地验证
./scripts/selftest.sh                  # 全流程自测（改 yh / 平台接口 / SDK / 模板后必跑）
cd console/backend && npm test          # 单元测试
git commit -am "..." && git push
./release.sh                           # 跑测试 → main 推到 release
```

`release.sh` 先跑 `bash -n yh && npm test && ./scripts/selftest.sh`，不过不发。推送后：

1. 平台机器上的 `yh agent` 每轮先自更新（`self_update`）：拉 `release` → 新 `yh` 语法检查通过才切换
2. `console/` 有变化 → 在平台机器上重新构建控制台并上线
3. `platform/` 有变化 → 重新加载平台组件（Caddyfile 换过会自动重建 Caddy）
4. 结果发通知群、记在 `backups/deploy-history.tsv`；失败保留旧版本

> 部署目录里有本地改动会让自更新失败（`checkout` 被挡住）。要改就提交，走发布。

### B. 插在平台上的应用

每个应用在自己的仓库里开发，`yh-app.json` 声明发布方式：

```json
{ "deploy": { "branch": "release", "mode": "auto" } }
```

- `mode: auto` → agent 每 `WATCH_INTERVAL` 秒查一次发布分支，有新提交就拉取、构建、上线，**失败自动回滚**并通知
- `mode: manual` → 只在控制台提示有新版本，管理员在「管理 → 应用 → 发布」或 `./yh update <code>` 手动上

**自动发布要同时满足 4 个条件**，缺一个就不跟踪：

| 条件 | 不满足时 |
| --- | --- |
| 应用是**从 Git 接入**的（`apps/<code>/.source` 以 `git:` 开头） | 本机目录接入（`path:`）的应用不自动发布 |
| 仓库里有合法的 `yh-app.json` | 安装时就会报错拒绝 |
| 清单里 `deploy.mode` 是 `auto` 或 `manual` | ⚠️ 缺 `deploy` 块或写了别的值时**静默不跟踪** |
| 应用没被停用（没有 `.stopped`） | 停用期间不发布；恢复后下一轮补上 |

分支取 `deploy.branch`，没写默认 `release`。出厂模板（`templates/*/yh-app.json`）已经带上自动发布。

### C. 手动操作速查

```bash
./yh status                    # 各应用状态、内存、版本
./yh doctor                    # 全面自检（含隧道、公网访问、应用域名）
./yh public-check              # 从公网访问一次入口（agent 每 5 分钟自动查）
./yh up console                # 重新构建控制台并上线
./yh start                     # 重读 yh.env，起 / 重启平台与隧道
./yh logs console -f           # 控制台日志；应用：./yh logs <code>
./yh history                   # 发布记录
./yh update <code>             # 手动发布某个应用
```

### D. 把内网独立服务挂到子域名（`EXTRA_TUNNELS`）

内网机器上有个**不归平台管**的服务（比如本机 3005 端口的一个阅读器），想用 `notes.example.com` 对外访问：在 `yh.env` 里配 `EXTRA_TUNNELS`，`yh` 会在同一条隧道上多开一条转发。

> **这不是托管应用。** 平台只管转发：进程自己负责常驻，登录自己负责。
> **域名一通就是公网可访问的，不经过平台登录。** 服务自己没有鉴权的话，先接统一认证（登记成外部应用，见开发中心 `/dev/sso`、`/dev/oidc`）或加别的保护，再开隧道。

1. **本机把服务跑起来并常驻**，先确认 `curl http://127.0.0.1:3005` 有响应（只监听 `127.0.0.1` 就够了）
2. **`yh.env` 加一行**（多条用英文逗号分隔，不要带空格）：
   ```bash
   EXTRA_TUNNELS=notes.example.com=host.docker.internal:3005
   ```
   等号右边是「frpc 容器里访问得到的地址:端口」：宿主机上的服务写 `host.docker.internal`，局域网里别的机器写它的 IP
3. **`./yh start`**：重新生成 `platform/frpc.toml`，有变化时自动重启隧道客户端（一两秒）。写错的条目当场报出来并跳过，不影响平台和其余条目
4. **云服务器放行这个域名**：它要**签得到证书**、请求**转给 frps 的 `127.0.0.1:7080`**。用 `cloud/install.sh` 装的服务器，给这个域名加一段（先备份 Caddyfile，`caddy validate` 通过再 `systemctl reload caddy`）：
   ```caddyfile
   notes.example.com {
   	reverse_proxy 127.0.0.1:7080
   }
   ```
   云服务器用「按需签证书 + 校验接口白名单」的，把域名加进白名单即可
5. **验证**：`./yh doctor` 里每条额外隧道有三项——「已在云端登记」「内网服务连得上」「公网访问」

| 现象 | 原因 |
| --- | --- |
| `yh start` 报 `EXTRA_TUNNELS 里的…已跳过` | 格式应为 `<域名>=<地址>:<端口>`；域名不带 `http://` 和路径；不能和平台域名、应用域名相同 |
| doctor：已在云端登记 ✗ | 改完没 `yh start`；或域名被别的隧道客户端占了（`docker logs yh-frpc` 里有 `router config conflict`） |
| doctor：内网服务连得上 ✗，访问是 404 | 服务没在运行（隧道本身是通的） |
| HTTPS 握手失败 / 证书错误 | 云服务器没放行这个域名（第 4 步） |

Linux 上默认没有 `host.docker.internal`，`platform/compose.yml` 已给 frpc 加了 `host-gateway`。改了 `yh` 的隧道部分跑 `./scripts/tunnel-test.sh`。

### E. 应用独立域名（`APPS_URL`）

**为什么**：不配时代码应用挂在控制台同一个域名下（`/apps/<code>/`），和控制台**同源**，应用页面里的脚本能读到打开它的人的控制台登录凭证（含管理员）。配了以后应用换到独立域名，和控制台不同源，读不到。背景见 [提案-应用独立域名](提案-应用独立域名.md)。

**效果**：应用地址变成 `https://apps.one.example.com/apps/<code>/`（**路径不变，只换域名**，各应用自带的 SDK、cookie 路径、相对地址都不用改）；控制台域名下的老地址 302 跳到新域名的同一路径；应用域名上不提供控制台页面和接口。

**切换（一次性）**：

1. **DNS**：把应用域名解析到云服务器（泛解析只管一级：`*.example.com` 管不到 `apps.one.example.com`）
2. **云服务器**：重跑 `cloud/install.sh` 并加上 `APPS_DOMAIN=apps.one.example.com`；云服务器用「按需签证书 + 白名单」的，把这个域名加进白名单
3. **平台机器**：`yh.env` 加 `APPS_URL=https://apps.one.example.com`，执行 `./yh start`。它会生成应用域名的路由、隧道加上这个域名、把每个应用重新上线（换地址、换统一登录回调）
4. **验证**：`./yh doctor` 里「应用域名：本机路由」「应用域名：控制台不在这个域名上」「公网访问 https://apps…」都应 ✓；浏览器打开一个应用，地址栏是应用域名，能正常登录
5. **回退**：把 `APPS_URL` 清空，`./yh start`，应用自动回到 `/apps/<code>/`

> 外部应用不受影响（本来就在别的域名）；轻应用跑在沙箱 iframe 里，本来就和控制台不同源。

### F. 公网巡检报警

「断了要有人知道，不能等用户先发现」，两头各查一份：

| 谁查 | 查什么 | 发到哪 | 什么时候发 |
| --- | --- | --- | --- |
| 平台机器上的 `yh agent`（自动，不用配） | 每 5 分钟从公网访问 `PUBLIC_URL/health`，配了 `APPS_URL` 也查应用域名 | 控制台「系统设置 → 发布通知」的群机器人 | 连续 2 次不通发一条，恢复了再发一条 |
| 云服务器上的 `cloud/healthcheck.sh`（cron） | 同上 | `health.env` 里的 `ALERT_WEBHOOK` | 同上；**平台机器关机、断网时只有它报得出来** |

用 `cloud/install.sh` 装的云服务器，带上 `ALERT_WEBHOOK=<飞书 / 钉钉 / 企业微信群机器人地址>`（钉钉加签再加 `ALERT_DINGTALK_SECRET`）执行就会装好并发一条测试通知。手动装：

```bash
mkdir -p /opt/yh-one-health && cd /opt/yh-one-health   # 把仓库里的 cloud/healthcheck.sh 拷过来
cat > health.env <<'ENV'
DOMAIN=one.example.com
APPS_DOMAIN=apps.one.example.com
ALERT_WEBHOOK=<群机器人地址>
ALERT_DINGTALK_SECRET=
ENV
chmod 600 health.env && chmod +x healthcheck.sh
./healthcheck.sh --test                                   # 群里应收到「巡检已开启」
echo "*/5 * * * * root /opt/yh-one-health/healthcheck.sh >/dev/null 2>&1" > /etc/cron.d/yh-one-health
```

钉钉机器人的「自定义关键词」可以填「以虎 One」。改了巡检相关的代码跑 `./scripts/health-test.sh`。

## 3. 首次部署 / 换机器

给一家公司从零装一套：按 [部署手册](部署手册.md) 做——平台机器上一条 `./install.sh --company <代号> --url … --apps-url … --frp-server <云服务器 IP>`，云服务器上一条 `cloud/install.sh`，再打开浏览器完成初始化。公司安装默认是**更新包方式**（不跟踪 `release` 分支，升级由那家公司在控制台点）；本节说的「跟踪 `release` 自动更新」只适用于用 `./install.sh --git` 原地安装的、以虎自己维护的实例。

换机器：新机器装好后，从旧机器的 `backups/` 拷出 `yh_console.sql.gz` → `./yh restore console backups/<时间>/yh_console.sql.gz`，`yh.env` 沿用旧的（密钥要一致）。

## 4. 回滚

| 场景 | 做法 |
| --- | --- |
| 平台新版本有问题 | 在 `main` 上 revert 后重新 `./release.sh`；紧急时在平台机器上 `git checkout <上一个好提交>` → `./yh up console` |
| 应用新版本有问题 | 自动发布失败会**自动回滚**；手动：在应用仓库里 revert 后再发布，或用控制台日志里的「更新前备份」`./yh restore <code> backups/<时间>/app_<code>.sql.gz` |
| 应用独立域名有问题 | 清空 `APPS_URL`，`./yh start` |

## 5. 验证：流量真的走隧道

```bash
ssh root@<云服务器 IP> 'docker ps --format "{{.Names}}" | grep ^yh-'   # 期望无输出：服务器上不跑平台容器
curl -I https://one.example.com                                      # 期望 200 / 302
./yh status && ./yh doctor                                           # 平台机器上
docker logs --tail 20 yh-frpc                                        # 有 login to server success
```

隧道断开时，云服务器 Caddy 返回内置的「平台暂时连不上」提示页——看到它就是**平台机器没开机或 frpc 没连上**。

## 6. 排查

| 现象 | 先查什么 |
| --- | --- |
| 域名打不开，显示「平台暂时连不上」 | 平台机器是否开机；`docker ps` 里 `yh-frpc`、`yh-caddy` 是否在跑；`docker logs yh-frpc` |
| 域名 404 / 502 | `./yh status` 看 yh-caddy、yh-console；`./yh up console` 重建 |
| 控制台里的操作一直「排队中」 | agent 没在跑：`./yh autostart` 或手动 `./yh agent`；看 `backups/agent.log` |
| 控制台显示 agent「未连接」 | agent 每 30 秒上报一次，超过 3 分钟没上报就显示未连接；查 agent 进程和 `backups/agent.log` |
| 推了 `release` 但没自动上线 | 平台机器有没有网络；`git ls-remote origin release`；`backups/agent.log`；`.deploy.lock` 是否残留（确认没有发布在跑后移走它并重启 agent） |
| 平台自更新失败通知 | 部署目录有本地改动（`git status`）——恢复干净工作区，或删 `backups/.self-failed` 后重试 |
| 证书签不下来 | 云服务器 Caddy 是否放行这个域名；Caddy 日志 |
| macOS 上 `yh` 报 `unbound variable` | `yh` 里变量后紧跟中文字符——写成 `${VAR}`；**必须保持 bash 3.2 兼容** |

## 7. 红线（不要做）

1. **不要把服务绑到 `0.0.0.0`**（`LOCAL_HTTP_BIND` 保持 `127.0.0.1`），否则同内网可以绕过隧道直连
2. **不要在部署目录里手工改源码**——会让平台自更新失败，改动必须走提交
3. **不要在 `release` 分支上直接提交**——只由 `./release.sh` 更新
4. **不要把平台容器放到公网服务器上**——它只做门
5. **不要手改 `platform/frpc.toml`、`platform/caddy/apps/*`**——由 `yh` 生成，改 `yh.env` 后 `./yh start`
6. **平台机器要常开**——关机 = 线上不可用（云端巡检会报警）
7. `yh.env`、`platform/console.env`、`apps/*/.env` 权限 600，**永不入库**（`.gitignore` 已排除）
