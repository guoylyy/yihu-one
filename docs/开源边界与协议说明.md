# 以虎 One · 开源边界与协议说明

> 状态：**已确认** · 2026-10-10
> 对应需求文档 REQ-10、决策点 6.5：**A 档（基础框架开源，业务应用与客户数据私有）+ Apache-2.0**，版权人 Yihu Technology。

## 一、开什么、不开什么

| 开源（本仓库） | 不开源（各自私有） |
| --- | --- |
| 控制台：后端、前端、开发中心文档 | 以虎和客户的**业务应用**（插在平台上的代码应用、轻应用、AI 助手、Skill） |
| `yh` 命令行、安装与升级脚本、自测脚本 | **客户数据**：数据库、备份、`yh.env` 等密钥和配置 |
| 平台编排（`platform/`）、云端入口（`cloud/`） | **客户交付资料**：部署记录、客户定制、合同与报价 |
| 应用模板（`templates/`）与 SDK | 以虎内部的运营、发布、值班流程文档 |
| 架构、部署、发布、接入规范等**通用**文档 | 「以虎 One」名称与 LOGO 的商标权（见第二节） |

判断一样东西放不放进开源仓库：**换一家公司拿去部署，它还有没有用？** 有用（框架、工具、通用文档）就开；只对以虎或某个客户有意义（业务、数据、交付记录）就不开。

## 二、协议

- **Apache License 2.0**（仓库根目录 `LICENSE`，已在用）
  - 任何人可以使用、修改、分发、商用，包括拿去服务自己的客户
  - 包含**专利授权**：贡献者把相关专利授权给使用者；起诉别人侵犯该专利的，授权自动终止
  - 要求保留版权和协议声明、标明改动
- **商标不随代码授权**（Apache-2.0 第 6 条）：别人可以用代码，但不能以「以虎 One」的名义或 LOGO 提供产品和服务
- **版权人**：Yihu Technology，写在仓库根目录的 `NOTICE`（`LICENSE` 保持 Apache-2.0 原文——里面的 `Copyright [yyyy] [name of copyright owner]` 是协议附录里的填写示例，不改）
- 第三方依赖：直接依赖里除一个外都是 MIT / BSD / Apache-2.0，与 Apache-2.0 兼容。**例外：`@openhex-ai/agent-sdk`（OpenHex 模型接入）的 LICENSE 还是占位文件，写明「最终协议未定，替换前不要再分发」**。已改成可选依赖：本仓库只是引用它、不分发它；对外分发控制台镜像时用 `--build-arg OMIT_OPTIONAL=1` 构建，镜像里就不带它（OpenHex 模型在那种镜像里不可用，会给出提示）。拿到它的正式协议后可以去掉这条限制。新增依赖前确认协议（不引入 AGPL、SSPL 等传染性或限制商用的协议）

## 三、怎么赚钱（与开源不冲突）

代码免费，**卖的是「启用包」和服务**：

- 部署与开台：按隧道转发标准装好平台、接好登录和通讯录、预置开台内容
- 管理员手册、外部应用登记 SOP、员工 Agent 使用培训
- 业务应用的定制开发（私有，不进本仓库）
- 运维与升级服务

## 四、贡献

- 外部：Issue / Pull Request，规则见 `CONTRIBUTING.md`；安全问题走 `SECURITY.md` 的私密渠道
- 内部：同样走 PR，`main` 开发、`release` 只由 `./release.sh` 推
- 合并前必须通过单元测试、前端构建和 `scripts/selftest.sh`
- 贡献默认按 Apache-2.0 授权（协议第 5 条），暂不要求签 CLA

## 五、还没定的

- `@openhex-ai/agent-sdk`（OpenHex 模型接入）的正式协议：拿到之前保持可选依赖，对外分发镜像时不装（见第二节）
- 各公司的部署记录、现网服务器信息不放进本仓库，放在私有仓库或内部知识库
