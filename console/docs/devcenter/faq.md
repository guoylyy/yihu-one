# 错误与常见问题

平台接口统一返回 `{ "code": 0, "data": … }`；出错时 `code` 非 0，`message` 是中文原因，HTTP 状态码同时反映错误类型。

| 现象 / message | 原因 | 处理 |
| --- | --- | --- |
| `redirect_uri 不在该应用登记的回调地址中` | 回调地址和登记的不同源，或路径不在登记路径下 | 登记与实际完全一致，注意 `127.0.0.1` ≠ `localhost`、端口、结尾斜杠 |
| `client_id 无效` | code 写错，或应用不是统一认证类型 | 「管理 → 应用」里确认 |
| `该应用已停用` | 应用被管理员停用 | 找管理员 |
| `client_secret 错误` | 密钥不对或已被重置 | 托管应用重新 `yh up <code>`；外部应用找管理员重置 |
| `code 已使用` / `code 已过期` | code 只能用一次，5 分钟有效 | 回调里只换一次；检查是否被浏览器重复请求 |
| `你没有使用「XX」的权限` | 用户不在应用的可见范围 | 管理员在「管理 → 应用 → 设置」调整可见范围 |
| `state 校验失败` | 会话 Cookie 丢了（跨域、换了主机名），或用户收藏了回调地址 | Cookie 用 `SameSite=Lax`；让用户从平台重新打开 |
| 使用数据 `userId 不存在` | 上报了工号或姓名 | `userId` 用统一认证返回的 `user.id` |
| 使用数据 `action 需为小写字母开头…` | 命名不合规 | 改成 `quote.compare` 这种 |
| AI 助手没有调用我的工具 | 清单里没写 `mcp` / 用户看不到应用 / MCP 端点连不上 / 描述写得让模型看不出什么时候该用 | 逐项检查；平台后端日志会打印 `[appTools] xxx MCP 不可用` |
| 工具返回 401 | 没带或没校验 Bearer token | 用 SDK 的 `userFromToken` / `user_from_token` |

**本地开发没有平台怎么办？** 不配 `YH_CLIENT_ID` 等变量时 SDK 不启用，应用按匿名模式运行。需要联调登录时，`yh init --test` 起一套测试平台，登录页有「开发登录」可以任选用户。

**应用打开显示「还没上线，或已停用」？** 路由不存在：应用没上线、被停用，或 code 写错。管理员在「管理 → 应用」看状态，或在服务器上 `yh status`。
