# 版本更新说明

以虎 One 的版本号是 `主版本.次版本.修订号`（语义化版本）。**0.x 是测试版（Beta）**：功能还在快速迭代，个别界面和接口可能调整，调整会写在这里和 [变更记录](/dev/changelog)。加功能升次版本号，只修问题升修订号；接口稳定后发 1.0。

当前版本在左侧栏底部、右上角头像菜单「关于」里可以看到；管理员在「管理 → 概览」里看升级。

## v0.6.4 · 2026-10-17

修订版：应用可以用平台的钉钉 / 飞书凭证。没有不兼容的改动。

- **用平台的钉钉 / 飞书凭证**：应用要调钉钉 / 飞书开放接口（比如人事考勤拉打卡）时，不用再配一遍 AppKey / Secret——平台把「管理 → 登录方式」里那个企业内部应用的 access_token 发给可信应用（管理员安装的托管应用、管理员登记的外部应用），密钥不出平台，每次发放都留痕。能调哪些接口看管理员在钉钉 / 飞书开发者后台给那个应用开了哪些权限。新接口 `GET /api/open/channel-token`，SDK `ws.channelToken()`。见 [应用信息与消息](/dev/notify)

升级：控制台「管理 → 概览」点「升级」，或执行 `./yh upgrade`；离线把 `yihu-one-0.6.4.tar.gz` 和 `.sig` 一起拷过去执行 `./yh upgrade --package yihu-one-0.6.4.tar.gz`。没有数据库结构变化。人事考勤 0.2.5 起用这个接口拉钉钉 / 飞书打卡

## v0.6.3 · 2026-10-17

修订版：控制台里移除应用不再卡在「正在移除」。没有不兼容的改动。

- **操作结果不会丢**：在控制台里移除、停用、发布应用时，宿主机上做完了，但交回结果那一下控制台的数据库正好卡住（比如 Docker 正在删应用镜像），结果就悄悄丢了——页面一直显示「正在移除 …」，已删的应用还列着。现在 `yh agent` 确认控制台收到才算数，重试约 30 秒，还不行就存下来，控制台恢复后按顺序补发

升级：控制台「管理 → 概览」点「升级」，或执行 `./yh upgrade`；离线把 `yihu-one-0.6.3.tar.gz` 和 `.sig` 一起拷过去执行 `./yh upgrade --package yihu-one-0.6.3.tar.gz`。没有数据库结构变化。已经卡住的操作：升级后 30 分钟内会标成「执行超时」，应用在宿主机上已经移除的，在「管理 → 应用」里再点一次「移除」即可

## v0.6.2 · 2026-10-17

修订版：登录后回到原来那一页。没有不兼容的改动。

- **统一认证保留应用的页面地址**：应用用 hash 路由（如 `/apps/hr/#/people`）时，没登录打开某一页，登录后以前会落到应用首页，现在回到这一页。应用不用改（前提是未登录跳授权、回调跳回都用 HTTP 302，平台 SDK 就是这样）；标准 OIDC 客户端不受影响。见 [统一认证](/dev/sso)

升级：控制台「管理 → 概览」点「升级」，或执行 `./yh upgrade`；离线把 `yihu-one-0.6.2.tar.gz` 和 `.sig` 一起拷过去执行 `./yh upgrade --package yihu-one-0.6.2.tar.gz`。没有数据库结构变化。

## v0.6.1 · 2026-10-17

修订版：应用里能「退出 / 换账号」。没有不兼容的改动。

- **从应用退出平台登录**：新地址 `/logout?redirect=/apps/<code>/`——退出平台登录、到登录页，换个账号登录后直接回到这个应用。以前应用的「退出」只清自己的会话，回来时平台还登录着，会原样再登进来，没法换人（比如测试员工、负责人看到的界面）。账号密码、钉钉、飞书、企业微信登录后都能回到应用地址
- **SDK**：JS `ws.logoutUrl(req)`、Python `ws.logout_url(headers)`，应用的 `/logout` 清掉自己的会话后 302 过去。见 [统一认证 · 会话建议](/dev/sso)

升级：控制台「管理 → 概览」点「升级」，或执行 `./yh upgrade`；离线把 `yihu-one-0.6.1.tar.gz` 和 `.sig` 一起拷过去执行 `./yh upgrade --package yihu-one-0.6.1.tar.gz`。没有数据库结构变化。应用要用新的退出方式，换上新版 SDK 并把 `/logout` 改成跳 `logoutUrl`。

## v0.6.0 · 2026-10-15

新功能：平台文件存储（七牛云）。没有不兼容的改动。

- **文件存储**：管理员在「管理 → 系统设置 → 文件存储（七牛云）」填 AccessKey / SecretKey、存储空间、区域、下载域名，点「测试连接」逐步检查（上传、查询、用下载域名取回、删除），哪一步不通直接说原因。课件、视频、图片这类大文件从此不用放进应用的代码仓库，也不用每个应用自己配密钥
- **应用怎么用**：开放接口 `/api/open/storage/*`（应用凭证）——拿上传凭证直传七牛（大文件不经过平台）、拿下载地址（私有空间带签名，默认 1 小时）、查询 / 列举 / 删除；每个应用只能读写自己的目录。JS / Python SDK 新增 `ws.storage`（`put` / `get` / `url` / `uploadToken` …）。见 [文件存储](/dev/storage)

升级：控制台「管理 → 概览」点「升级」，或执行 `./yh upgrade`；离线把 `yihu-one-0.6.0.tar.gz` 和 `.sig` 一起拷过去执行 `./yh upgrade --package yihu-one-0.6.0.tar.gz`。没有数据库结构变化；文件存储默认关闭，配好再启用。用到文件存储的应用要换上新版 SDK（`/sdk/yh-one.mjs`、`/sdk/yh_one.py`）。

## v0.5.0 · 2026-10-15

次版本：本地部署更容易装、更容易配。没有不兼容的改动。

- **开通向导**：装好后管理员登录就进入向导，一步步配好公司信息、外观、大模型、登录方式、人员、消息通知和应用。每一步保存后立即生效，可以跳过，中途关掉下次接着来；「管理」页右上角随时回来，首页「开始配置」卡片显示还没配的项
  - **大模型**：选厂商、贴 API Key，地址和模型名自动带出，可以顺手加上向量模型；加完当场测试
  - **登录方式**：钉钉 / 飞书 / 企业微信各自列出去哪建应用、要开的权限、回调地址（一键复制）；「保存并测试连接」逐项告诉你哪里不对（凭证错、IP 不在可信列表、通讯录权限没开……），测通了才打开登录
  - **人员**：从钉钉 / 飞书同步通讯录（先预览），或者用 Excel（.xlsx）/ CSV / 从 Excel 直接粘贴导入：部门写成「研发部/前端组」自动建，能指定部门负责人和管理员、给初始密码；已有的人跳过
  - **消息通知**：「发一条给我」验证个人消息能不能推到手机；群机器人发测试消息
  - **应用**：一键安装官方应用（FDE 交付管理）；宿主机的 yh agent 没在运行时会提醒
  - **完成**：汇总哪些配好了、哪些跳过了；一键开通自己的每日经营简报；下载一页「开通报告」留档
- **安装更省事**：`./install.sh` 不带参数时一问一答，最后给出等价的完整命令；新增**内网模式** `--intranet`：没有域名、不对外，员工用 `http://<服务器 IP>` 打开（钉钉 / 飞书 / 企业微信登录要外网回调，内网模式用账号密码）
- **Docker 安装**：机器上只有 Docker（Windows / macOS 的 Docker Desktop、群晖等 NAS）也能装：`docker run … ghcr.io/guoylyy/yihu-one:0.5.0`，参数和 `install.sh` 一样；常驻 agent 跑成容器 `yh-agent`，Docker 起来它就起来。见部署手册「Docker 安装」
- **控制台镜像预先构建好**：更新包方式装的平台，安装和升级时直接下载发布好的控制台镜像（amd64 / arm64，国内走镜像加速），不再现场构建：装得快，也不用访问 npm。拉不到时自动退回现场构建；配了 OpenHex 模型的平台照旧现场构建
- 修复：`install.sh --no-openhex`（`CONSOLE_OMIT_OPTIONAL=1`）构建出的控制台启动时崩溃

升级：控制台「管理 → 概览」点「升级」，或在平台机器上执行 `./yh upgrade`；不能联网的机器把 `yihu-one-0.5.0.tar.gz` 和 `.sig` 一起拷过去执行 `./yh upgrade --package yihu-one-0.5.0.tar.gz`。没有数据库结构变化。升级后管理员在「管理 → 开通向导」里能看到哪些还没配。

次版本：给老板的应用。没有不兼容的改动。

- **定时任务**：任何人都能设，比如「每周五 17:00 总结本周项目进展」。以本人身份运行，**只能查、不能改**，结果推到本人手机并存成对话（个人中心 → 定时任务）

- 助手设定新增「全部只读工具」；应用可见范围新增「部门负责人」
- 修复：应用发布了新的 AI 工具后，平台最多要等 5 分钟才能用上；现在发布完立即可用

## v0.1.1 · 2026-10-13

修订版：修复几个在真实环境里碰到的问题，建议所有 0.1.0 平台升级。

- **AI 助手：应用工具多时不再报错**。平台工具加上应用的 AI 工具超过模型上限（OpenAI 兼容接口一般 128 个）时，所有能看到这些应用的人的助手都会请求失败；现在工具多的应用改为先查后调（`find_app_tools` / `call_app_tool`），写操作照样要确认。装 [FDE 交付管理](https://github.com/guoylyy/yihu-fde) 这类工具多的应用之前，先升级到 0.1.1
- **知识库**：向量化每批最多 10 条（部分向量模型一次只接这么多）、网络错误自动重试一次、出网优先 IPv4，修复在火山方舟等服务上知识库一直处理不完的问题
- **没开工具的 AI 助手**：改用不提「调用工具」的规则，修复 DeepSeek 等模型把工具调用标记当正文输出
- **登录方式配置说明**：开发中心新增 [登录方式配置](/dev/login-setup)，逐项列出钉钉、飞书、企业微信要开的权限和地址；企业微信可信域名的验证文件可以直接填在「登录方式 → 企业微信应用」里，不用动服务器
- **更新包签名**：从这个版本起更新包带签名。**升级到 0.1.1 以后，这台机器只接受以虎签名的更新包**（控制台点升级、`yh upgrade`、离线包都一样），从发布页下载的包都带签名，不用做什么

升级：控制台「管理 → 概览」点「升级」，或在平台机器上执行 `./yh upgrade`。不能联网的机器把 `yihu-one-0.1.1.tar.gz` 和 `.sig` 一起拷过去执行 `./yh upgrade --package yihu-one-0.1.1.tar.gz`。
