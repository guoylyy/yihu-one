# 创作中心：自己做应用

每个人都可以在「创作中心」做应用，给自己用、分享给同事，或者上架到全公司的应用市场。**大部分情况不用写代码。**

| 类型 | 适合做什么 | 怎么做 | 谁能做 |
| --- | --- | --- | --- |
| **AI 助手** | 制度问答、数据查询、写周报/通知、某个流程的向导 | 写提示词、勾选它能用的工具、挑模型 | 所有人 |
| **轻应用** | 预约、报名、登记、周报收集、计算器、小看板 | 用对话描述需求，AI 生成页面，右边马上能试 | 所有人 |
| **外部应用** | 公司已经有、部署在别处的系统 | 填地址；要统一登录和 AI 工具见 [统一认证](/dev/sso)、[接入 AI 助手](/dev/mcp) | 所有人 |
| **代码应用** | 需要自己后端、数据库的正式系统 | Git 仓库，按 [应用部署规范](/dev/deploy) | 管理员、开发者 |
| **Skill** | 教 Agent 做某件事的「做法」：周报模板、合同审查清单、数据分析步骤 | 上传含 `SKILL.md` 的文件夹或 ZIP，或让你的 Agent 通过 MCP 上传，见 [Skill 中心](/dev/skills) | 所有人 |

## 发布给谁

在编辑页右上角点「发布…」：

| 范围 | 什么时候生效 |
| --- | --- |
| 仅自己 | 马上 |
| 指定同事或部门 | AI 助手、轻应用马上生效；外部应用要管理员审核 |
| 上架到全公司市场 | 一律要管理员审核 |

代码应用每次提交都要审核（代码要跑在平台机器上）。审核通过前，用户用的一直是上一个生效的版本；被打回的话，编辑页顶部会写原因，改好重新发布即可。

所有修改先存成**草稿**（自动保存），发布才生效。「版本」里能看到每一次发布，任何一个历史版本都可以「基于它修改」。

## 做一个 AI 助手

1. 新建 → AI 助手，写名称和一句话简介
2. **提示词**：告诉它是谁、帮用户做什么、按什么步骤、有什么规矩、用什么格式回答。可以用「用示例开头」
3. **工具**：勾选它能调用的工具（平台通用的，和你能看到的应用提供的）。别人用你的助手时，工具**以他自己的身份和权限**执行；他没权限的工具自动不可用；写操作都会先弹确认卡片
4. **欢迎语、开场问题**：打开时显示，开场问题可以一键发送
5. 右边**试聊**：用的就是当前草稿，只有你能看到
6. 发布

同事装了之后，在「AI 助手」页左上角切换到你的助手。

## 生成一个轻应用

1. 新建 → 轻应用
2. 在左边说清楚：**给谁用、要记录哪些信息、谁能看到什么、有什么规则**。例如：「做一个会议室预约工具：选会议室、日期、时间段和用途；已经被约的时段不能再约；所有人都能看到预约列表，只能取消自己的」
3. AI 生成页面，右边马上能操作（预览和正式版共用数据）
4. 不满意就接着说怎么改：「加一个按日期筛选」「提交后清空表单」「手机上按钮太小」
5. 发布

轻应用能做什么、不能做什么见 [轻应用 SDK](/dev/lite)。数据在编辑页「数据」里可以导出成 Excel 能打开的 CSV。

## 额度

管理员在「管理 → 审核与市场 → 市场设置」里设：每人最多几个 AI 助手 / 轻应用、每个轻应用最多多少条数据、轻应用每人每天能调几次 AI。长期没人用的应用，创作中心会提示你归档。
