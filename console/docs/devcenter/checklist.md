# 上线检查清单

上线前逐项核对。前三组是必须的。

## 身份与安全（必须）

- [ ] `client_secret` 只在服务端环境变量里，没有进前端代码、代码库、聊天记录、文档
- [ ] 回调里校验了 `state`
- [ ] 登记的回调地址只包含自己的域名，生产环境用生产地址（`127.0.0.1` 和 `localhost` 不能混用）
- [ ] 用户主键用 `user.id`，没有用姓名或工号当主键
- [ ] 应用内的权限按部门 / 角色判断过；没配置过的人默认最小权限
- [ ] 接口未登录返回 401，页面收到 401 能重新走授权

## 使用数据（必须）

- [ ] 关键操作都调用了 `track()`，`action` 命名为「对象.动作」
- [ ] `detail` 里没有原文、手机号、身份证号、密码
- [ ] 影响他人的配置修改有上报（谁改的、改成什么）
- [ ] 平台断开时应用照常可用（SDK 上报失败只打日志）

## 联调（必须）

- [ ] 用普通用户、部门主管、管理员三种身份各走一遍
- [ ] 用了钉钉登录的，在钉钉里打开过一次
- [ ] 在「管理 → 应用 → 使用数据」能看到自己上报的事件

## 部署（必须）

- [ ] 仓库根目录有 `yh-app.json` 和 `Dockerfile`，`/health` 免登录返回 200
- [ ] 前端请求、链接都是相对路径，挂在 `/apps/<code>/` 下能正常用
- [ ] 数据只写 `DATABASE_URL` 和 `/data`
- [ ] 有 `release.sh`，`TEST_CMD` 是真实的测试命令

## AI（用到时）

- [ ] 查询类工具声明了 `readOnlyHint: true`，会改数据的没有声明
- [ ] MCP 端点校验了 access_token，不允许匿名
- [ ] 工具的 `description` 和参数说明写清楚了，在平台问过助手一句验证
- [ ] 通过 MCP 做的操作也上报了使用数据（`"via": "ai"`）
